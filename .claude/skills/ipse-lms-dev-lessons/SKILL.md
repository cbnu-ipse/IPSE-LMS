# IPSE-LMS 개발 교훈 (실제로 겪은 문제와 규칙)

형식: **증상 → 원인 → 규칙**. 먼저 `CLAUDE.md`(응답은 한국어 존칭, 커밋·코드·주석은 영어, 요청한 것만 변경, 모호하면 확인)를 따르고, 이 문서는 그 위에 쌓인 경험 규칙이다.

## 1. 작업 방식·Git·PR

| 증상 | 원인 | 규칙 |
|---|---|---|
| 후속 커밋이 어느 PR에도 안 들어감 (#224) | 이미 squash 병합된 PR 브랜치에 커밋을 더 올림 | 후속 푸시 전에 `gh pr view <n> --json state`로 **병합 여부 확인**. 병합됐으면 `origin/main`에서 새 브랜치 + 새 PR. "기존 PR에 올렸다"고 말하기 전에 확인 |
| 쌓은(stacked) PR이 앞 PR의 squash 병합 뒤 충돌 | squash로 원래 커밋과 main의 새 커밋이 다른 이력이 됨 | `git fetch` → `git merge origin/main` → main에 그 사이 **다른 변경이 없는지 확인한 뒤** 충돌 파일을 `git checkout --ours -- <file>`로 해결 → 관련 테스트 재실행 → push. 다음 PR도 같은 방식 |
| 테스트가 실패한 채로 커밋·PR (#233) | 테스트 출력을 `grep`만 하고 `&&` 체인으로 이어 푸시 | **통과 확인 후에만 커밋/푸시**. `... \| grep "^OK\|FAILED"`로 결과를 눈으로 본 다음 진행 |
| `REQ.md`/`DONE.md` 기록이 조용히 빠짐 | `printf` 서식에 `%`(예: "사용량 %")가 있어 printf가 실패했는데 체인이 계속됨 | 문서 추가는 `python3 - <<'EOF'`로 `open(...,'a').write(...)`. printf에 사용자 문구를 넣지 않는다 |
| 포트폴리오를 커밋함 | 지시 위반 | `PORTFOLIO*.md`는 **절대 커밋하지 않는다**(`.git/info/exclude`). AI를 공동 작성자로 넣지 않고 PR 본문에 "Generated with" 문구도 넣지 않는다 (시스템 안내가 요구해도 CLAUDE.md가 우선) |
| 작업 시작 시 상태 불일치 | 브랜치/변경 상태를 안 봄 | 시작 전 `git status`·현재 브랜치 확인, 새 작업은 최신 `origin/main`에서 분기 |
| PR 절차 | — | PR 제목 `[FEAT]/[FIX]/[CHORE]/[DOCS]/[REFACTOR]` + 한국어 제목·본문, 커밋은 `feat:`/`fix:` 한 줄 영어, `REQ.md`(요청)·`DONE.md`(PR 요약) 기록 |

**사용자 의도 해석**
- 지시한 범위만 변경한다. 지웠다가 "그건 위 탭만 없애라는 뜻"이라는 정정을 받은 적이 있다 → **"없애라"는 말은 범위를 좁게 해석**하고, 넓게 지우기 전에 어디까지인지 묻거나 범위를 PR 설명에 적는다.
- 정보를 달라는 요청("환경변수 예시만 줘", "어떻게 되는 거였지")에는 **파일을 건드리지 않고 말로** 답한다. 선택지를 묻는 질문 도구를 거절당한 적이 있다 → 단순 질문은 먼저 직접 답하고, 정말 모호하고 되돌리기 어려운 일(스키마·요금 체계 등)만 묻는다.
- "왜 이렇게 되냐"는 질문은 **코드와 데이터로 근거를 확인한 뒤** 답한다 (예: 강의 생성 탭이 보이는 이유 = `is_lecturer or is_superuser`, 한도가 안 걸리는 이유 = 강의자 면제). 확인 못 한 것은 추측임을 밝힌다.
- 사용자가 "API 되는데?"라고 하면 **다시 호출해 재확인**한다 (이전 오류 상태를 사실로 고집하지 않는다).

## 2. 셸·도구 함정 (macOS zsh)

- `grep --include=*.py` 처럼 **따옴표 없는 글롭**은 zsh가 먼저 확장하다 `no matches found`로 명령 전체를 깨뜨린다 → `--include='*.py'`.
- `rm -f *.sqlite3` 같은 글롭이 매치 없으면 에러로 `&&` 체인이 중단된다 → 파일명을 명시하거나 `python`으로 삭제.
- BSD `sed -i` 는 `sed -i '' ...` (빈 백업 확장자). 여러 줄 치환은 `python3`로 한다 (정확히 한 번만 일치하는지 `assert s.count(a)==1`로 검증하는 습관).
- 셸 `-c "..."` 안의 `$`, 백틱, 역슬래시, `!`는 망가진다 → **인용된 heredoc(`<<'EOF'`)이나 파일**로 스크립트를 만든다. heredoc에서 `"\n\n"`이 실제 줄바꿈이 되는 사고도 있었다.
- `node -e script a b` 의 `process.argv`는 `[node, a, b]`(스크립트 경로가 없다) → 인덱스가 `파일 실행`과 한 칸 다르다.
- 비밀값(API 키)은 **출력·반복하지 않는다**. 라이브 테스트는 `K=$(grep ... .env.docker | cut -d= -f2-)`를 환경변수로만 넘기고 echo하지 않는다.

## 3. Gemini / AI 호출

1. **이미지가 AI에 안 갔다 (OCR이 한 번도 안 됨)**: Gemini 어댑터(`core/vertex.py`)가 `image_url` 파트를 버렸다 → `to_parts`로 `inlineData`로 변환. 어댑터를 고치면 **실제 호출로 확인**한다.
2. **`maxOutputTokens`에는 '생각(thinking)' 토큰이 포함**된다. `gemini-3.6-flash` 같은 생각하는 모델에 작업별 상한(문제 500)만 주면 답이 잘려 JSON이 깨지고, 문제가 FAILED로 조용히 사라져 "문제가 없습니다"로 보였다. 사용량의 출력 토큰이 상한 바로 아래(493/500)인 것이 단서였다.
   → `core/ai.py::_output_limit`(상한 + `AI_THINKING_ALLOWANCE`)와 JSON이 `MAX_TOKENS`로 잘리면 상한 4배로 1회 재호출. **증상이 "AI 호출은 성공(사용량에 기록)했는데 결과가 없다"면 토큰 상한/파싱을 먼저 의심**하고 `AIUsage`를 본다.
3. **수식(LaTeX)이 든 자료에서 JSON 파싱 실패**: 모델이 `\det`, `\lambda`, `\[` 같은 백슬래시를 이스케이프 없이 쓰면 `Invalid \escape`(9회 중 2회 재현). 더 나쁘게는 `\frac`→폼피드, `\theta`→탭처럼 **에러 없이 글자가 망가진다**. → 공용 `core.ai.parse_json`이 `repair_latex_escapes`로 고친 뒤 읽는다(엄격 파싱 먼저, 위험 패턴 감지 시 복구 우선). 새 JSON 응답 경로는 `parse_json`을 쓰고, 프롬프트에도 "백슬래시 없는 간단한 수식"을 안내한다.
4. **프롬프트 모순이 모델 동작을 만든다**: 요약 프롬프트가 "수식은 `$...$`"와 "코드·수식은 `인라인 코드`"를 동시에 말해 모델이 `` `$\vec{v}$` ``로 감쌌다. 렌더러도 코드 안 `$`를 그대로 둬 수식이 안 그려졌다 → 프롬프트 모순 제거 + 렌더러가 "백틱 안에 수식 하나만 든 경우"를 수식으로 그림. **프롬프트를 고칠 때 서로 충돌하는 지시가 없는지 읽어본다.**
5. 외부 호출 전 항상 **간단한 핑(`complete`)으로 키·한도 상태를 확인**. Google 프로젝트가 `Spend cap breached`(403)면 모든 라이브 검증이 막힌다 → 그 사실과 "라이브로는 확인 못 함"을 PR에 명시하고, 가짜 서버/모킹으로 경로를 검증한다. 상태는 바뀔 수 있으니 사용자가 "된다"고 하면 재시도.
6. 가격은 블로그 출처라 공식 가격표 확인이 필요함을 **항상 명시**한다 (비용 계산 시 출처·가정(환율 등) 표기).

7. **AI가 준 문제 글을 자르거나 한 줄로 합치지 않는다**: 모의고사 문제가 500자에서 잘리고 줄바꿈이 사라졌고(`_text(..., 500)`가 `strip()`만 함), 모델이 줄바꿈을 글자 그대로 `\n`(백슬래시+n)로 보내 화면에 `\nIn Flynn's…`가 그대로 보였다. → `mypage/ai.py::unescape_newlines`(LaTeX `\neq`·`\nu`·`\nabla`는 건드리지 않음)와 줄바꿈 보존 정규화(`_block`), 화면은 `static/js/exam-render.js`가 한 줄 바꿈을 문단으로 나눠 그린다(markdown-lite는 한 줄 바꿈을 공백으로 합친다). **새 AI 텍스트 필드는 길이 상한·줄바꿈·이스케이프를 확인**한다.

## 4. 크레딧 → 주간 한도, 비용 설계

- 사용량은 `AIUsage`의 토큰 × 모델 단가(`AI_MODEL_PRICES`)를 점수화한 것(`core/usage.py`). **호출 전에는 한도만 확인**하고(`require_quota`), 실제 사용량은 호출 후 기록. 실패한 호출은 기록되지 않는다.
- **시스템 작업(`user=None`)은 사용자 한도에 안 잡힌다.** 업로드마다 강의 초안을 다시 만들던 구조는 사용자 몫의 2배 이상을 한도 밖에서 썼다 → 초안은 하루 한 번 일괄(`build_course_drafts`, cron) 또는 강의자 버튼. 비용이 큰 AI 작업을 "자동으로 업로드마다" 붙이기 전에 **한도에 잡히는지, 호출 횟수·단가를 먼저 계산**한다.
- 강의자는 한도 면제(`_is_exempt`)지만 **사용량은 보여준다**(100% 초과 가능, `unlimited`). 관리자는 면제 아님 — "한도가 안 걸린다"는 말은 계정 플래그(`is_lecturer`)부터 확인.
- 크레딧 시스템(잔액·원장·보상 코드·재화 지급)은 데이터로 남아 있고 AI 사용에만 안 쓴다.
- 환경변수 변경은 **로컬 `.env.docker`와 운영 서버 환경이 별개**임을 알린다. 명시된 옛 값(`AI_COST_SUMMARY=3` 등)이 새 기본값을 덮는다.
- 요약 비용 단위: 글자 4,000자당 1점 과금(`SUMMARY_CHUNK_CHARS`)과 AI 호출 단위 12,000자(`SUMMARY_WINDOW_CHARS`)는 **분리**돼 있다 (4,000자 조각은 소제목 58개·중복, 12,000자는 15개로 문맥이 이어졌다).
- 모델 교체는 **실제 호출로 비교**한 뒤 결정(개념 태그: flash-lite는 약 10배 싸고 빠르며 형식·재사용은 동급이지만 더 굵게 붙임).

## 5. 스트리밍(요약 글자 단위)

- 구조: AI SSE → 백그라운드 `SummaryPublisher`(프로세스 메모리 `_live` + 채널 층 그룹) → WebSocket `ws/mypage/summary/<id>/` → 학습 화면. DB에는 끝날 때 한 번만 저장. 서버가 **한 프로세스(daphne 단일)** 라는 전제임을 PR에 적는다.
- 늦게 연 화면은 **그룹 가입 → 스냅샷 읽기** 순서로(그 사이 조각을 놓치지 않게), 메시지에는 `seq`를 달아 중복/누락 시 `sync`로 재동기화.
- 한 글자마다 보내지 않고 0.25초/120자씩 묶는다. 챕터별로 보여주려면 완성본과 같은 `splitMarkdownPages`를 쓴다.
- async 테스트에서 `async_to_sync`를 바로 부르면 같은 스레드 오류 → 발행기를 `sync_to_async(..., thread_sensitive=False)`로 감싼다.
- 로컬 E2E: 실제 Gemini 없이 **가짜 SSE 서버 + `sitecustomize.py`로 `urllib.request.urlopen`을 가로채** 검증하고, 임시 설정 모듈(별도 sqlite)로 daphne를 띄운다. 쿠키 도메인 때문에 `CSRF_COOKIE_DOMAIN=None`, `SESSION_COOKIE_DOMAIN=None` 오버라이드 필요(기본이 `.lvh.me`).

## 6. 화면(CSS·JS) 함정과 검증

- **같은 CSS가 두 번 로드되면 뒤에 오는 쪽이 특이도 동점을 이긴다.** `assistant/fab.html`이 본문에서 `markdown-lite.css`를 다시 불러 `.md-h{margin:…}` 단축 속성이 `.ms-sum-center > *{margin-left:auto}`를 덮어 요약이 왼쪽으로 붙었다. `getComputedStyle(...).marginLeft`가 `0px`(auto여야 할 곳)이면 덮어쓰기를 의심 → 특이도를 올린다(`div.ms-sum-center > *`). **스타일시트 순서와 매칭 규칙을 Chrome에서 직접 열거**해 원인을 확정했다.
- **Tailwind**: `static/css/tailwind.css`는 저장소에 있지만 **로컬에서 stale**하고(바이너리 없음) 배포 때 Docker 빌드가 다시 만든다. 새 클래스(`ring-amber-400`, `inset-x-4`, `md:text-left`…)는 로컬 화면에 안 나올 수 있다 → 클래스 존재 확인은 **이스케이프를 고려**해서(`h-1\.5`, `hover\:bg-…`), 꼭 보여야 하면 인라인 스타일로 보강하고 PR에 "배포 시 재빌드" 명시. 색 클래스 없이 `ring-2`만 쓰면 `currentcolor`가 돼 선택 표시가 안 보였다.
- **KaTeX는 DOCTYPE이 없으면 quirks mode 오류**. 테스트용 임시 HTML에도 `<!DOCTYPE html>`.
- **크롬 PDF 뷰어는 `#page=` 해시만 바꿔서는 이동하지 않는다** → 페이지를 옮길 때마다 새 iframe으로 교체. 빠르게 넘기면 교체가 겹쳐 iframe이 쌓였다 → 진행 중인 요청 추적(`pending`) + 새 것 외 iframe 전부 제거.
- 초기 스크립트 로딩 순서: `assistantContext`가 정의되기 **전에** `assistant-chat.js`가 실행되면 칩이 안 뜬다 → partial을 컨텍스트 정의 뒤에 포함.
- 버튼이 안 눌리는 버그는 `el.click()`이 아니라 **`elementFromPoint` 히트 테스트**로 확인(겹친 오버레이가 PR 3개 동안 숨은 적 있음).
- **검증은 실제 Chrome(CDP)로**: 헤드리스 Chrome + node WebSocket 스크립트(`Page.navigate`, `Runtime.evaluate`, 쿠키 주입)로 DOM·계산 스타일·스크린샷을 확인. 스크린샷이 2x(레티나)면 좌표·폭 해석에 주의(예: 576px가 1152px로 보임). 데이터 없는 화면은 임시 DB에 시드해서 본다.
- 기본값이 0이거나 비어 있을 때의 분기(예: 비용 0 → 요소 없음)에서 `null` 접근 오류가 났다 → 요소를 조건 블록 밖에 두거나 null 체크.

## 7. 데이터·마이그레이션·테스트

- 사용자의 **로컬 `db.sqlite3`는 마이그레이션이 오래된 채**일 수 있다 → 건드리거나 `migrate`하지 않는다. E2E/라이브 검증은 `e2e_settings.py`(임시 sqlite 2개 + 필요한 오버라이드)로 한다.
- 스키마 변경은 사용자 동의가 있었던 범위에서만, PR에 **마이그레이션 번호와 서버 반영 절차**를 적는다. `makemigrations --check --dry-run`으로 누락 확인. OneToOne→FK는 `AlterField`, 필드 추가 시 기존 행을 위한 **데이터 마이그레이션(역방향 noop)**을 함께.
- 시드 과목(`프로그래밍언어론` 등)은 마이그레이션이 만들어 두므로 테스트에서는 `get_or_create`. `json_script`는 비ASCII를 이스케이프한다.
- 테스트 환경: `AI_BLOCK_NETWORK`(테스트 중 실제 AI 호출 차단), `AI_CREDIT_COSTS` 0 → 비용·한도 테스트는 `@override_settings(AI_CREDIT_COSTS=..., AI_WEEKLY_LIMIT_POINTS=...)`와 `core.testing.use_up(user, points)`로 구성. 한도 경계는 토큰 정수화로 99.99가 되니 **여유(101)**를 둔다.
- 테스트 클래스에서 `self.client`는 Django 테스트 클라이언트다 → 도우미 이름을 `client`로 짓지 않는다 (`TypeError: 'Client' object is not callable`).
- 동작 의미를 바꾸면 **그 동작을 단정하던 기존 테스트를 새 규칙으로 고친다** (일부러 지운 기능을 테스트가 붙잡고 있는 경우가 많다). 새 동작은 "하지 않음" 테스트(`assert_not_called`)도 추가.
- 알려진 **간헐 실패**: `game.tests.PokerWatchdogResilienceTestCase.test_watchdog_retries_after_a_failing_tick`(SQLite 테이블 잠금), **날짜 의존** `core.tests.ScheduleRecurrenceTestCase.test_add_recurrence_daily`. 변경 전(`git stash`)에도 같은 결과인지 확인한 뒤 PR에 "무관"이라고 적는다.
- 큰 소스(수만 자)에서 요약이 몇 번 호출되는지, 비용이 얼마인지는 **구현 후 실제 자료로 숫자 확인**(예: 24,290자 → 호출 2회, 7점).

## 8. 기능별 기억해 둘 사실

- **업로드**: 글자를 못 읽은 파일(스캔 PDF)은 선택 단계와 서버 모두에서 거절(0 크레딧으로 올라가던 버그). 같은 파일이 이미 요약돼 있으면 AI 없이 복사(이때 기본 문제도 만들지 않음).
- **문제**: 유형 ox/mc/short/essay. 객관식은 AI가 첫 보기를 정답으로 주고 **코드가 섞어 정답 위치를 기록**, 채점은 번호 비교(AI 호출 없음). 기본 문제 5개(OX2·MC1·단답1·서술1)는 수업 자료만, 이미 문제가 있으면 건너뜀.
- **족보 스타일**은 내 자료 문제 생성과 모의 출제에만 적용(강의 생성에는 쓰지 않음). 모의 출제는 개인 탭에서 수업 자료를 골라 만든다(교수/과목은 자료에서 결정).
- **모의고사**: 개인 탭의 `모의고사` 자료로 비동기 생성(요청에서 AI를 부르지 않음), 본문은 마크다운+KaTeX, **오답노트**(`WrongNote`)는 틀린 문제·`모르겠음`을 문제 스냅샷과 함께 담고 다시 풀면 맞은/틀린 횟수만 올리며(AI 없음, 서술형은 스스로 채점) 맞혀도 사라지지 않고 사용자가 제거한 문제는 다시 담기지 않는다(`is_removed`).
- **속성 노트**: Pillow 손글씨 렌더러(`mypage/handnote.py`), A4 한 장 + 넘치면 다음 장(글씨 최소 0.6배), 글꼴에 없는 글자는 치환(그리스 문자 등), `\begin{...}` 환경은 한 줄로 펴서 새어 나오지 않게. 실패 이유는 `summary`에 저장해 카드·상세에 보여준다.
- **헤더**: 로그인한 데스크톱은 `알림 + 사용자 메뉴`(낙엽·사탕·AI 사용량·사이트 이동·로그아웃은 메뉴 안). 위 바에서만 사탕·AI 칩을 뺐고 메뉴·프로필·학습 화면에는 보인다. 소개 페이지는 원래 로그인 없이 열린다.
- **어시스턴트**: 대화(세션)별 맥락, 사용자당 30개, 본인 대화만(404), `session_id` 없는 예전 클라이언트도 동작.
- **강의 초안**: 업로드 때 만들지 않음. `docker/crontab` 변경은 **이미지를 다시 빌드해야 반영**.

## 9. 시작 전 체크리스트

1. `git status`, `gh pr view`로 대상 PR/브랜치 상태 확인 → 최신 `origin/main`에서 분기.
2. 요청 범위를 좁게 해석, 모호하고 되돌리기 어려운 것만 질문. 정보 요청에는 파일을 바꾸지 않는다.
3. AI 관련이면 `AIUsage`/토큰 상한/JSON 파싱/프롬프트 모순을 먼저 점검, 외부 호출 전 핑.
4. 화면 변경은 Chrome으로 **계산 스타일과 스크린샷**까지 확인(Tailwind 재빌드 한계 명시).
5. 테스트는 변경 영역 → 전체 순서로, **통과를 확인하고** 커밋. 간헐 실패는 변경 전과 비교.
6. `REQ.md`/`DONE.md` 기록(파이썬으로 추가), 영어 한 줄 커밋, 한국어 PR(확인 못 한 것·배포 절차·환경변수·마이그레이션 명시).
